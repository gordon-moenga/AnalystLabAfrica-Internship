# Week 1: FinTrust Digital Bank — Understand & Plan

## Overview

This repository contains my Week 1 work for the FinTrust Financial Intelligence and Digital Banking Support project under the AnalystLab Africa Experience Lab.

The focus of my work was to understand the business problem, assess the available data, define the analytical requirements, and plan the business intelligence solution.

## Completed Objectives

### 1. Business Understanding

- Identified the key business questions FinTrust management should be able to answer using customer and transaction data.

- Identified the business decisions that data analysis could support and the stakeholders who would benefit from the analytical outputs.

### 2. Data Understanding and Profiling

Reviewed and profiled both the Customer and Transaction datasets.

The profiling covered:

Number of records and columns
Field names and data types
Categorical, numerical, identifier, and date/time fields
Dataset relationships
Missing values
Initial data quality observations

The Customer dataset contains 1,500 records and 12 columns.

The Transaction dataset contains 12,000 records and 11 columns.

Missing values in Device_Type and Location, with each field containing 96 missing records.

Identified that Transaction_DateTime is currently stored as an object and will require conversion to a proper datetime type during data preparation.

### 3. Analytical Questions

Developed eight analytical questions covering:

Customer behaviour
Customer segmentation
Transaction activity
Transaction value
Transaction channels
Transaction status
International transactions
Risk review patterns

The questions were designed to be answerable using the available datasets.

### 4. KPI Planning

Defined seven proposed KPIs to measure FinTrust's business and transaction performance.

These include:

Total Transaction Value
Total Transactions
Active Customers
Average Transaction Value
Transaction Success Rate
Risk Review Rate
International Transaction Rate

Each KPI was documented with its definition, business importance, and required data.

### 5. Dashboard Planning

Created a dashboard plan covering:

Overall transaction performance
Customer intelligence
Transaction intelligence
Risk indicators
KPI cards
Trend analysis
Customer and transaction segmentation
Dashboard filters

The dashboard plan is designed around the identified business questions rather than simply displaying available data.

### 6. Initial Analysis Plan

Developed an analysis workflow covering data profiling, data preparation, customer analysis, transaction analysis, risk pattern analysis, KPI development, dashboard development, and business insight generation.
